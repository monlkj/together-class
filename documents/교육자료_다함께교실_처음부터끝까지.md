## 1\. 우리가 만든 것 — 다함께교실이란?

### 1-1. 문제 의식 (왜 만들었나?)

교실에는 **한국어가 아직 어려운 친구**(이주배경 학생)가 있을 수 있다.  
교과서·선생님 말씀·가정통신문이 어려우면, 공부가 아니라 **언어**가 먼저 장벽이 된다.

**다함께교실**은 그 장벽을 조금 낮추려고 만든 교육용 앱·웹이다.

### 1-2. 할 수 있는 일 (기능 목록)

| 기호 | 기능 | 한 줄 설명 |
| :---- | :---- | :---- |
| F1 | 교과서 번역 | 사진을 찍거나 올리면 글자를 읽고 다른 언어로 번역 |
| F2 | 실시간 통역 | 마이크로 말하면 다른 언어로 바꿔 들려줌 |
| F3 | 토론 친구 | 단원 주제로 AI와 토론·토의 |
| F4 | 인물 인터뷰 | 교과서 속 인물에게 질문 |
| F5 | RAG | 교과서 지문을 미리 넣어 두고, AI가 그 내용을 근거로 답함 |
| F6 | 로그인·학습 기록 | 누가 어떤 활동을 했는지 저장 |
| F7 | 가정통신문 | 가정통신문 사진 → 번역·요약 |
| (추가) | 받아쓰기·글자 연습 | 듣고 쓰기, 따라 쓰기 연습 |
| (교사) | 학생 인증·학급 기록·자료 등록 | 같은 반 학생 관리, RAG·인물 등록 |

지원 언어 예: 한국어, 러시아어, 중국어, 베트남어, 우즈베크어, 카자흐어.

### 1-3. 앱과 웹을 둘 다 만든 이유

|  | 앱 (모바일) | 웹 (PC·브라우저) |
| :---- | :---- | :---- |
| 도구 | React Native \+ Expo | Next.js |
| 잘 맞는 곳 | 교실 태블릿, 카메라·마이크 | 교무실 PC, 큰 화면, 교사 관리 |
| 순서 | **먼저** 만듦 (1차) | **나중에** 확장 (2차) |

같은 “두뇌”(도메인·공통 타입)를 쓰고, **화면만** 앱/웹에 맞게 그린다.

## 2\. 큰 그림 — 앱 · 웹 · 서버가 나뉜 이유

### 2-1. 비유로 이해하기

상상해 보자.

1. **앱 / 웹** \= 식당의 **홀·메뉴판** (손님이 만지는 곳)  
2. **Supabase Edge Functions** \= **주방** (비밀 레시피·API 키가 있는 곳)  
3. **데이터베이스(Postgres)** \= **창고** (회원·기록·교과서 조각을 보관)

손님(앱)이 주방에 직접 들어가 비밀 소스를 만지면 안 된다.  
그래서 앱은 “주문만” 보내고, 주방이 AI(번역·OCR)를 부른다.

\[학생 폰/PC\]

    │  로그인, 버튼 클릭

    ▼

\[앱 또는 웹\]  ──주문──►  \[Edge Function\]  ──►  \[OpenAI / Vision 등\]

    │                         │

    │                         ▼

    └──── 기록 저장 ◄──── \[Supabase DB\]

### 2-2. “모노레포”란?

한 GitHub 저장소 안에 **앱·웹·공통 코드·서버**가 같이 들어 있는 구조다.

together\_class/          ← 저장소 루트 (여기가 집)

├── apps/

│   ├── mobile/          ← 스마트폰·태블릿 앱

│   └── web/             ← 브라우저 웹

├── packages/

│   ├── domain/          ← 비즈니스 규칙·유스케이스 (공통)

│   └── shared/          ← 언어 코드, 화면 문구, 연습 단어 등

├── supabase/

│   ├── functions/       ← 서버(Edge Functions)

│   └── migrations/      ← DB 테이블을 만드는 SQL

└── docs/                ← 지금 읽는 설명서들

**왜 이렇게?**  
“번역 결과 타입”을 앱과 웹에 각각 쓰면 나중에 하나가 바뀌면 다른 쪽이 깨진다.  
`packages`에 두고 **한 번만** 정의한다.

## 5\. 가장 중요한 규칙 — API 키는 숨긴다

### 5-1. API 키란?

OpenAI·Google Vision 같은 서비스에 “우리 팀 맞아요”라고 증명하는 **비밀번호에 가까운 문자열**이다.  
인터넷에 올라가면 **다른 사람이 우리 돈으로 AI를 쓸 수 있다.**

### 5-2. 절대 규칙 (외우기)

1. 앱·웹 코드에 OpenAI 키를 **넣지 않는다.**  
2. 앱·웹은 AI를 **직접** 부르지 않는다. **Edge Function만** 부른다.  
3. `.env` 파일은 GitHub에 **올리지 않는다.** (`.gitignore`에 있음)  
4. Vercel(웹 배포)에는 Supabase **anon** 키만 넣는다. `service_role`·OpenAI 키는 **넣지 않는다.**

### 5-3. 어디에 무엇을 넣나?

| 저장 위치 | 넣어도 되는 것 | 넣으면 안 되는 것 |
| :---- | :---- | :---- |
| 앱/웹 `.env` | `NEXT_PUBLIC_SUPABASE_URL`, anon 키 | OpenAI, Vision, service\_role |
| Supabase Edge Secrets | OpenAI, Vision, service\_role 등 | (공개 저장소에 커밋하지 말 것) |
| Vercel Environment | `NEXT_PUBLIC_SUPABASE_*` 두 개 | OpenAI, Vision, service\_role |

학생 활동: “이 키가 코드에 보이면 위험하다”를 서로 찾아보는 퀴즈를 해도 좋다.

## 6\. 클린 아키텍처 — 코드도 “역할”을 나눈다

### 6-1. 의존성 방향 (화살표는 안쪽으로만)

화면(presentation)

    →  응용(application / hooks)

        →  도메인(domain: 규칙·유스케이스)

              ↑

     바깥 세계(카메라, Supabase)는 domain을 직접 건드리지 않고

     ports(약속) → infrastructure(실제 연결)로만 들어온다.

- **domain**은 React도 Supabase도 import하지 않는다.  
- 그래서 **앱과 웹이 같은 규칙을 공유**하기 쉽다.

### 6-2. 새 기능을 만들 때 순서 (학생용)

1. “사용자가 무엇을 누르고, 무엇이 나오는가?”를 한 문장으로 쓴다.  
2. 이미 있는 Edge Function / 훅이 있는지 `docs`·코드를 찾는다.  
3. **한 화면 또는 한 함수만** 고친다.  
4. 에뮬레이터·브라우저에서 확인한다.  
5. 커밋 메시지를 **한국어로** 짧게 남긴다.

Cursor에게 부탁할 때도:

> “한 번에 한 기능만. 클린 아키텍처 규칙을 지켜 주세요.”

## 7\. 1차: 모바일 앱 만들기 (Expo)

### 7-1. 실행 방법

cd C:\\react\_project\\together\_class

npm run mobile

- 터미널에 QR이 나오면 폰 **Expo Go**로 스캔  
- 또는 안드로이드 에뮬레이터에서 `a`  
- 자세한 순서: [SETUP\_초보자용.md](http://./SETUP_초보자용.md)

### 7-2. 화면이 늘어나는 방식

1. `MainScreen`에 기능 카드 추가  
2. `XxxScreen.tsx` 화면 파일 생성  
3. 필요하면 `hooks`에서 Edge 호출  
4. 로딩·에러 메시지를 **친절한 한국어**로 표시

화면 이름 규칙: `TranslateScreen`, `DebateScreen`처럼 **XxxScreen**.

### 7-3. 앱에서 특히 신경 쓴 것

| 주제 | 왜? |
| :---- | :---- |
| 카메라·마이크 권한 | 번역·통역에 필요. 거부되면 안내 문구 |
| 태블릿 레이아웃 | 교실은 태블릿이 많음 → 그리드·비율 조정 |
| 다국어 UI | 같은 화면도 언어 칩으로 문구 변경 (`getXxxScreenCopy`) |
| 손글씨·받아쓰기 | 캔버스 → 이미지 → Edge OCR |
| 교사 기능 | 학생 인증, 학급 기록, 학습자료(RAG) 등록 |

### 7-4. 앱 ↔ 서버 호출 한 줄 흐름

예: 교과서 번역

1. 학생이 사진 촬영  
2. 앱이 이미지를 base64로 만듦  
3. `translate` Edge Function 호출  
4. 서버가 OCR \+ 번역  
5. 결과를 화면에 표시하고, 가능하면 학습 기록에 저장

## 8\. 2차: 웹 만들기 (Next.js)

### 8-1. 왜 웹을 만들었나?

- 교사 PC에서 **학급 기록·학생 인증·자료 등록**이 편하다.  
- QR 없이도 브라우저 주소로 시연할 수 있다.  
- 앱과 **같은 Supabase**를 쓰므로 데이터가 이어진다.

### 8-2. 실행

npm run web

브라우저: [http://localhost:3000](http://localhost:3000)

로그인하지 않으면 로그인 화면으로 보낸다 (`AppShell`).

### 8-3. 웹 주소 ↔ 화면

| 주소 | 화면 |
| :---- | :---- |
| `/` | 홈 |
| `/translate` | 교과서 번역 |
| `/interpret` | 통역 |
| `/debate` | 토론 |
| `/persona` | 인물 인터뷰 |
| `/dictation` | 받아쓰기 |
| `/writing` | 글자 연습 |
| `/notice` | 가정통신문 |
| `/records` | 학습 기록 (교사는 학급 대시보드) |
| `/approval` | 학생 인증 (교사) |
| `/admin` | 자료 관리 (교사) |

전체 표: [화면목록.md](http://./화면목록.md)

### 8-4. 앱과 웹이 “같아 보이려면”

같은 Edge·같은 DB를 써도, **화면 코드가 다르게** 짜여 있으면 버그가 난다.

예 (수업 사례):

- 인물 인터뷰: 앱은 `textbooks.curriculum_unit_id`로 단원을 찾는데,  
  웹은 없는 컬럼을 봐서 “자료 없음”이 떴다.  
- **해결:** 웹도 앱과 같은 방식으로 고치고, GitHub에 올린 뒤 Vercel이 다시 배포했다.

수업 포인트: “서버에 데이터가 없어도 안 보이는 게 아니라, **읽는 코드가 틀려도** 안 보인다.”

### 8-5. 디자인 (Binance 스타일)

- 배경: 짙은 검정 (`#0b0e11`)

## 9\. 기능별로 무엇을 배웠나

각 기능을 **기술 키워드**와 연결해 복습한다.

### 9-1. 교과서 번역

- **OCR:** 사진 → 글자  
- **번역:** 글자 → 다른 언어  
- 웹: 파일 업로드 / 앱: 카메라·갤러리

### 9-2. 통역

- **STT:** 말 → 글자  
- **번역** \+ (웹) 브라우저 **TTS**로 읽기  
- 마이크 권한, 녹음 시작/종료 토글

### 9-3. 토론 · 인물 인터뷰

- **LLM 대화** \+ 이전 메시지(history)  
- **RAG:** 교과서 조각을 검색해 근거로 사용  
- 단원·주제를 DB/공통 목록에서 고름

### 9-4. 받아쓰기 · 글자 연습

- 단어 덱: `packages/shared`의 `PRACTICE_WORDS`  
- 정답 비교: `normalizePracticeAnswer`  
- 손글씨: 캔버스 → PNG → `handwriting` OCR  
- 정답 시 포인트 RPC (`add_student_points`)

### 9-5. 가정통신문

- 이미지 → 번역 → (선택) 요약  
- 웹은 **언어 하나 선택 후** 번역·요약 2단계 (앱과 맞춤)

### 9-6. 교사 콘솔

- **학생 인증:** 같은 학교·학년·반 가입 학생 승인  
- **학급 기록:** Edge `class-records`  
- **자료 관리:** RAG ingest, 페르소나 등록

## 10\. Git · GitHub — 저장과 공유

### 10-1. 왜 쓰나?

- “어제 잘 되던 코드로 되돌리기”  
- 선생님·친구와 **같은 코드** 공유  
- Vercel이 GitHub를 보고 **자동 배포**

### 10-2. 자주 쓰는 말

| 말 | 뜻 |
| :---- | :---- |
| commit | “이 시점의 코드를 사진 찍듯 저장” |
| push | 그 사진을 GitHub에 올리기 |
| pull | GitHub에 있는 최신을 내 컴퓨터로 받기 |
| branch | 실험용 갈래 (처음엔 `master`만 써도 됨) |

### 10-3. 커밋 메시지 규칙 (이 프로젝트)

- **한국어**로 짧게  
- “무엇을”보다 **왜**가 보이게  
  - 예: `웹 인물 인터뷰가 교과서 단원 ID로 자료를 찾도록 고친다.`

### 10-4. 올리면 안 되는 것

- `.env`, 비밀번호, API 키  
- 개인정보가 잔뜩 있는 원본 PDF 대량 폴더 (`textbook/` 등) — 필요할 때만 상의

## 11\. Vercel — 웹을 세상에 공개하기

전체 클릭 순서: [VERCEL\_배포.md](http://./VERCEL_배포.md)

### 11-1. 한 줄 요약

GitHub에 올린 `apps/web`을 Vercel이 빌드해서  
`https://이름.vercel.app` 주소를 만들어 준다.

### 11-2. 학생이 꼭 맞출 설정

1. **Root Directory** \= `apps/web` (모노레포라서 필수)  
2. 환경변수 2개만:  
   - `NEXT_PUBLIC_SUPABASE_URL`  
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`  
3. Deploy 후 Supabase **Redirect URLs**에 그 주소 추가  
4. Build Override는 **굳이 켤 필요 없음** (`vercel.json`이 처리)

### 11-3. “Install Coding Agent Plugin”은?

배포 성공 화면에 나오는 **선택 광고**다.  
사이트 동작과 무관하니 **안 해도 된다.**

### 11-4. Functions deploy는?

`npx supabase functions deploy`는 **Vercel이 아니라 Supabase** 쪽이다.  
예전에 앱 테스트할 때 Functions를 이미 올렸다면, 웹만 배포할 때는 **생략해도 된다.**  
Functions 코드를 새로 바꿨을 때만 다시 배포한다.

## 12\. 자주 생기는 문제와 해결

| 증상 | 먼저 볼 곳 |
| :---- | :---- |
| 앱이 Supabase에 연결 안 됨 | `.env`의 `EXPO_PUBLIC_` 접두사, Expo 재시작 |
| 번역이 가짜(목) 응답만 나옴 | Edge Secrets에 API 키, `functions deploy` |
| 웹 로그인 후 바로 튕김 | Supabase Redirect URLs에 Vercel 주소 |
| 웹 빌드 실패: `@dahamkke/shared` 없음 | Vercel Root Directory가 `apps/web`인지 |
| 인물 인터뷰 “자료 없음” (앱엔 있음) | 웹이 단원 ID를 잘못 읽는지 (앱과 같은 매핑인지) |
| 마이크/카메라 안 됨 | 브라우저 권한, HTTPS(배포 주소) 여부 |
| 커밋에 `.env`가 들어감 | 즉시 키 교체(rotate), `.gitignore` 확인, 선생님께 알리기 |

## 14\. 용어 사전

| 용어 | 쉬운 설명 |
| :---- | :---- |
| Frontend | 사용자가 보는 화면 (앱·웹) |
| Backend | 화면 뒤에서 일하는 서버·DB |
| API | “이런 요청 하면 이런 답을 줄게”라는 약속 |
| Edge Function | Supabase가 실행해 주는 짧은 서버 프로그램 |
| OCR | 사진 속 글자를 컴퓨터가 읽기 |
| STT / TTS | 말→글자 / 글자→말 |
| LLM | 대화·번역에 쓰는 큰 언어 모델(AI) |
| RAG | 내 자료를 찾아 읽고 답하게 하는 방법 |
| RLS | DB에서 “내 것만 보기” 같은 행 단위 보안 |
| anon key | 앱이 Supabase에 붙을 때 쓰는 공개용 키 (그래도 Git에 막 올리면 안 됨) |
| service\_role | 모든 권한에 가까운 키 → **절대 클라이언트에 금지** |
| Monorepo | 여러 앱을 한 저장소에 모은 구조 |
| Deploy | 인터넷에서 접속 가능하게 올리는 것 |
| Vibe coding | AI와 대화하며 기능을 조금씩 만들어 가는 방식 |
